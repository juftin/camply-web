## Review verification

Independent review identified that `reservableType` is a selected-stay snapshot, not a daily-grid eligibility flag. For live `CO_50028` site 1269 on 2027-01-05, the `gad`/`gal` response reported daily `AVAILABLE` with a null snapshot and `ENTER_DATE` CTA; adding selected-stay `arv`/`lsy` changed the snapshot to `WEB_AVAILABLE` and CTA to `BOOK_NOW`. Other grid-available sites had `FIELD_AVAILABLE` snapshots. Removing that snapshot gate increased the complete sample scan from 85 to 115 available sites. Regression tests cover null, unavailable, call-center and field snapshots with later available nights, while excluding daily walk-up and call-center statuses. The frontend never references `callCenterReservable`; that flag is retained as metadata rather than interpreted as a phone-only restriction. Only the exact per-night `AVAILABLE` status is reported.

The reviewer verified the follow-up and reported no remaining actionable findings. All 32 focused provider/migration tests passed; the reviewer independently ran all 28 provider tests. The full backend suite was rerun after the final fix with 909 passed and 23 opt-in skips. Scoped Ruff/MyPy and pre-commit checks passed.

## Cookie lifecycle hardening

Synthetic HTTP regressions reproduced stale token headers after API Set-Cookie rotation and reuse of a known-invalid session after two 401 responses. Headers now derive from the actual request-scoped cookie jar for every API attempt, honoring domain/path/expiry and cookie deletion. For duplicate names, the first cookie in the HTTP client’s path-ordered request header wins, so an API-path rotation overrides an older root token. After an unsuccessful one-time refresh, the next operation bootstraps before calling the API. Tests additionally cover concurrent callers sharing one refresh. This does not claim live cookie-expiry acceptance: the expiry/rotation scenarios are synthetic. Generic 403 responses continue to fail; no proactive refresh timer or login-redirect handling was added without a verified expiry signal.

Cookie follow-up verification: final full backend run passed (915 tests, 23 opt-in skips), all 38 provider/migration regressions passed, and repository-wide `task check` passed. The reviewer reported no actionable findings and independently verified rotation, expiry, and duplicate-path cookie precedence.

The Providers page now lists ReserveAmerica in both popular/all sections in place of Yellowstone Lodges, with its booking URL, US coverage, camping features and rounded 1,000+ campground count. Frontend types, lint and all 340 tests passed. Desktop light/dark screenshots were inspected locally and on macOS CI run 42411836647; accepted baselines use the macOS captures to match CI rendering.

## Public URL correction

The API-accessible `a1` host also appeared in public links, where the user reported broken navigation. Public provider, campground and campsite links now target `https://www.reserveamerica.com`; API requests and cookie bootstrap retain explicit `a1` URLs. The original seed migration remains unchanged; a forward data migration corrects previously seeded URLs and preserves custom overrides. Regression tests verify both rendered provider-card links, generated booking destinations, API/session host isolation, URL migration round trips, and fresh/existing database upgrades. This environment still receives HTTP 403 from `www`, so successful public navigation is not claimed as a live automated acceptance check here.

Public URL verification: 918 backend tests passed (23 opt-in skips), all 341 frontend tests passed, and repository-wide `task check` passed. The reviewer independently verified the public-host/API-host split, frontend link regression, and guarded migration behavior with no actionable findings. PostgreSQL verification of the new URL migration remains delegated to CI because Docker is unavailable locally.
