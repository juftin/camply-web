## Recommended next changes

1. Fix autocomplete first. Reproduce the stale-selection race, keep Enter-to-full-results for an unselected query, and verify keyboard and screen-reader behavior. Improve destination links and retry in the same flow.
2. Make ScanForm explain and retain the camper's intent. Summarize the destination, coverage, and exact or flexible nights. Restore the draft after sign-in or notification setup, reuse Profile test sends, and make monitoring without delivery and duplicate recovery clear at save time.
3. Make Dashboard status and totals agree with eligibility and pagination. Validate the complete path from destination search to the provider's booking page with campers. Test Home suggestions and campground filters where users still struggle to find destinations.

## Design constraints that still apply

- Preserve the current app's theme and navigation, use one ScanForm dialog, and build on Explore, destination pages, Dashboard, Profile, and Found Campsites.
- Use the saved scan criteria and provider capability gates for what can be monitored. Present availability as observed, with freshness and an official reservation handoff.
- Preserve authentication, invitation, ownership, and scanning eligibility. Use camper-owned projections for user diagnostics and keep admin telemetry behind its role guard.
- Use current components and [application snapshot baselines](https://github.com/juftin/camply-web/tree/1751044/tests/frontend/snapshots/baselines) for visual acceptance. The [original wireframe](https://github.com/juftin/camply-web/blob/2f1ea85/specs/002-campsite-discovery/wireframes.html) uses fictional data and depicts the October UI.

The original [specification](spec.md), [plan](plan.md), and [implementation brief](implementation.md) capture the design rationale. Re-scope their task list around the table above before implementation. Explore maps, new channels, provider filters, area scans, enrichment, date edits, and alert summaries already cover parts of the later phases. Camper-facing delivery history, favorites or comparison, and trip organization remain separate proposals. This assessment is based on repository source and tests. Deployed capability checks, provider booking handoffs, and camper usability sessions remain pending.
