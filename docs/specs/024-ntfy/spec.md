# User-selected notification provider

Each user selects Pushover or ntfy as their notification provider. Exactly one provider receives each newly detected alert. Existing accounts default to Pushover. ntfy users subscribe to their own editable topic, initially the first seven characters of their user ID, and select ntfy.sh or a custom HTTP(S) server, including a path prefix. The deployment configures a public default subscription URL and optional private publish URL. When the publish URL is absent, it uses the subscription URL. Only the public URL is exposed to users. Each user can optionally override the default with a custom server used for both publishing and subscription. A dropdown offers the configured application server when present, ntfy.sh, or a user-provided server URL. Selecting the configured server follows current deployment defaults; the custom URL input appears only for the user-provided option. An optional bearer token supports protected publishing servers. Secrets and private deployment endpoints are never queued or exposed in profile responses.

Acceptance: only the currently selected provider’s settings are visible, and credentials/preferences save together; topics are editable, validated and unique; settings persist in all authentication modes; partial profile updates preserve other settings; suspended/ineligible accounts receive no alerts; both runtimes route summary/direct alerts only to the selected provider. Pending delivery is skipped when the user switches away from its original channel. Validate with mocked HTTP, API, migration, worker and UI tests.
