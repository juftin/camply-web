# Implementation plan

Add a per-user provider choice and ntfy settings with editable prefixed user-ID-based topics and a data migration. Extend current-user serialization, PATCH validation and Profile UI. Implement the existing provider interface using ntfy JSON publishing, explicit acceptance, finite timeouts, and no redirects. Allow private custom hosts for self-hosted deployments. Use shared deployment configuration for the public subscription and private optional publish URL; resolve publishing server-side in both adapters. Persist only an optional custom server override per user. Expose the effective public subscription server in Profile, without serializing private deployment endpoints. Use additive SQLite/PostgreSQL migrations to assign topics, preserve Pushover defaults, and convert generated topics to user-ID prefixes without overwriting customized or claimed topics. Dispatch only the selected provider through its Celery task or standalone outbox intent, retaining existing Pushover contracts. Revalidate provider choice and settings at delivery time, skipping queued alerts for a deselected channel.

Constitution check: async I/O, typed schemas, no new optional dependency coupling, migration for SQLite/PostgreSQL, mocked integration tests. Existing users retain Pushover as their default.

Test delivery uses a shared `camply.notifications` layer with worker compatibility imports, plus an authenticated API endpoint that validates draft settings and awaits explicit upstream acceptance without persisting changes. Profile tests the current form independently of saving, with pending/acceptance/failure feedback.

Review fixes: clear credentials on server edits and avoid inheriting a saved token when API drafts/partial updates change the publishing destination. Expose the public application-default option whenever a publish override is configured, even with ntfy.sh subscriptions. Use one shared account-insertion helper for automatic, Auth0 and administrator creation, retrying only generated-topic uniqueness conflicts before adding audit records. Add a random suffix on collision and keep the initial seven-character default otherwise. Bind save feedback to submitted values and restore subscribe-first guidance without restoring the combined URL section. Verify each behavior with regression tests; no schema migration is needed.
