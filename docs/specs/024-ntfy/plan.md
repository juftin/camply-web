# Implementation plan

Add a per-user provider choice and ntfy settings with editable user-ID-based topics and a data migration. Extend current-user serialization, PATCH validation and Profile UI. Implement the existing provider interface using ntfy JSON publishing, explicit acceptance, finite timeouts, and no redirects. Allow private custom hosts for self-hosted deployments. Use shared deployment configuration for the public subscription and private optional publish URL; resolve publishing server-side in both adapters. Persist only an optional custom server override per user. Expose the effective public subscription server in Profile, without serializing private deployment endpoints. Use additive SQLite/PostgreSQL migrations to assign topics, preserve Pushover defaults, and convert generated topics to user-ID prefixes without overwriting customized or claimed topics. Dispatch only the selected provider through its Celery task or standalone outbox intent, retaining existing Pushover contracts. Revalidate provider choice and settings at delivery time, skipping queued alerts for a deselected channel.

Constitution check: async I/O, typed schemas, no new optional dependency coupling, migration for SQLite/PostgreSQL, mocked integration tests. Existing users retain Pushover as their default.
