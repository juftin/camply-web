# Legacy Camply CLI inventory

**Audited**: 2026-11-08. **Baseline**: [juftin/camply v0.34.4](https://github.com/juftin/camply/releases/tag/v0.34.4), the latest published release observed during this audit. “v1” means the legacy product generation; the upstream release is not tagged v1.0. Runtime behavior below is a static source audit, supported by upstream tests, not a claim that old endpoints still work. New behavior is proposed, not implemented.

## Command inventory and replacement map

IDs in this document are coverage identifiers for the spec and future contract tests. “Gap” means the current repository does not expose the complete required public capability, even if private provider code already obtains some data.

| ID  | Legacy surface and behavior                                                                                                                                                                                                                                | Replacement and present gap                                                                                                                                                                                                 |
| --- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| C01 | `camply`, `--help`, per-command help, `--version`; `python -m camply` also invokes the old CLI. Rich help and a welcome/exit banner.                                                                                                                       | Preserve familiar commands and readable help; preserve current `python -m camply.cli`; add the legacy module entrypoint. Exact colors/banners are not contractual.                                                          |
| C02 | Root and relevant subcommand `--provider`; case-insensitive names; `CAMPLY_PROVIDER`; default `RecreationDotGov`. Command selection overrides root selection.                                                                                              | Alias registry maps legacy names to current identities; report availability/capabilities. Keep ID handling provider-scoped and string-based.                                                                                |
| C03 | Root and most commands `--debug/--no-debug`; root debug takes precedence when explicitly supplied. Rich tracebacks can show locals. `CAMPLY_LOG_HANDLER=rich/python`, `LOG_LEVEL`.                                                                         | Preserve switches and legacy logging environment names; use structlog with readable terminal/plain output and secret redaction, including debug.                                                                            |
| C04 | `providers [--debug/--no-debug]` lists registered search providers and descriptions.                                                                                                                                                                       | Show usable providers, legacy aliases and explicitly unavailable compatibility entries with reasons; no database/network required.                                                                                          |
| C05 | `recreation-areas --search TEXT --state CODE [--provider ...] [--debug/--no-debug]` finds parks/areas and IDs. Yellowstone is a fixed area; GoingToCamp lists deployments. State-only searches are rejected for these two providers.                       | Use `BaseProvider.search(entity_type="recreation_area")` for native providers. | C06 | `campgrounds --search TEXT --state CODE --rec-area ID --campground ID --campsite ID` with repeatable IDs, provider/debug. Most providers require at least one selector; Yellowstone and GoingToCamp permit browse. Site IDs can resolve parent facilities. | Use direct upstream search plus explicit ID/parent resolution capabilities. Feature 025 covers text/state/single-parent discovery, not site-to-parent or exact-ID lookups. Preserve selector validation for legacy aliases. |
| C07 | `list-campsites --campground ID --rec-area ID` (repeatable), provider/debug. Requires a parent selector. Lists names and IDs, not availability. Never require a scan or real availability; no test sends during help/config parsing.                                                                          |

Missing extra gives installation guidance.                                                    |

## Availability options and semantics

| ID  | Option(s)                                           | Legacy behavior                                                                                                                                                                                                                                                       | Proposed replacement                                                                                                                                                                                              |
| --- | --------------------------------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| S01 | `--rec-area ID`, `--campground ID`, `--campsite ID` | Each repeatable. Recreation.gov selects sites over campgrounds over areas. Other providers can require both parent and site; GoingToCamp requires exactly one deployment area.                                                                                        | Resolve to unique provider/campground/site targets, preserve provider-specific precedence and required context. Do not union ignored Recreation.gov parents.                                                      |
| S02 | `--start-date YYYY-MM-DD`, `--end-date YYYY-MM-DD`  | Repeatable, paired by position with equal counts; arrival inclusive, checkout exclusive. Overlapping windows union nights. Past starts clamp to local today; past end fails.                                                                                          | Preserve pairing/exclusive checkout, overlap deduplication and past-start clamp with warning. Use documented UTC day cutoff consistent with current engine. No future nights is a validation error.               |
| S03 | `--day NAME`                                        | Repeatable, full English names or MON/TUE/TUES/WED/THU/THUR/THURS/FRI/SAT/SUN, advertised case-insensitive.                                                                                                                                                           | Normalize names before lookup; restrict eligible nights before stay matching.                                                                                                                                     |
| S04 | `--weekends`                                        | Adds Friday and Saturday to selected weekdays; with `--day` it is a union. With no day restrictions, search all seven days.                                                                                                                                           | Preserve union semantics, including Sunday + weekends = Fri/Sat/Sun.                                                                                                                                              |
| S05 | `--nights INTEGER`                                  | Default 1. Builds sliding exact-length consecutive stays at the same site. If requested nights exceed the longest eligible run, silently reduces the request with a warning.                                                                                          | Preserve sliding exact-length stay output; reject impossible lengths instead of reducing them. Current web minimum-stay blocks need a separate CLI presentation step.                                             |
| S06 | No run-mode flag                                    | One live search; logs results; no external notification.                                                                                                                                                                                                              | Preserve. Empty successful search exits 0 and reports no matches.                                                                                                                                                 |
| S07 | `--continuous`                                      | Poll until availability is found, then exit.                                                                                                                                                                                                                          | Foreground async loop with immediate first check, bounded retries and cancellation.                                                                                                                               |
| S08 | `--search-forever`                                  | Implies continuous; continues after matches; suppresses already-seen identical availability across the run, even after disappearance/reappearance.                                                                                                                    | Preserve CLI lifetime suppression; keep web new-opening policy unchanged. Stop when all search nights expire.                                                                                                     |
| S09 | `--search-once`                                     | One cycle with continuous-mode notifications, suitable for cron; incompatible with explicit `--continuous` or `--search-forever` on flag path.                                                                                                                        | Preserve single notification cycle and validate conflicts in both flag and YAML paths.                                                                                                                            |
| S10 | `--polling-interval INTEGER`                        | Minutes; implies continuous, default 10, values below 5 clamp to 5. Engine also has `POLLING_INTERVAL` fallback, but CLI supplies 10 when omitted, so that environment fallback is not generally reached. Yellowstone has a separate 45-minute minimum configuration. | Preserve default/minimum with visible effective interval; honor stricter provider pacing and Retry-After. Do not claim `POLLING_INTERVAL` is a reliable legacy CLI option.                                        |
| S11 | `--notifications NAME`                              | Repeatable, case-insensitive; any explicit channel, including silent, implies continuous. Default silent. Console is always included alongside external channels.                                                                                                     | Fan out through common notification interfaces. Selected unsupported/misconfigured channels fail before provider IO.                                                                                              |
| S12 | `--notify-first-try`                                | Implies continuous. Normally the first immediate batch is capped at 5 external campsite notifications; warns about excess. Flag bypasses that cap but general batch limiting still caps at 20. Later retry/loop batches use 20.                                       | Preserve 5/20 limits, deterministic selection and visible suppressed counts. Flag does not mean unlimited.                                                                                                        |
| S13 | `--equipment NAME LENGTH`                           | Repeatable pairs; Recreation.gov matches any requested equipment type, case-insensitive, with per-type max length. Length 0 disables length restriction; CLI rounds numeric lengths and treats unparsable lengths as unrestricted.                                    | Preserve OR matching and 0 sentinel; document provider units (feet for Recreation.gov). Reject invalid/negative lengths. Use typed capability data, not broad campsite type as a substitute.                      |
| S14 | `--equipment-id ID`                                 | GoingToCamp deployment-specific equipment category; discovered with `equipment-types`.                                                                                                                                                                                | Public provider filter/capability required; validate scope and availability before running. Never silently ignore it.                                                                                             |
| S15 | `--yaml-config PATH`, `--yml-config PATH`           | Reads a search file instead of search options; see schema below.                                                                                                                                                                                                      | Keep both spellings and file precedence, with diagnostics for ignored explicit flags.                                                                                                                             |
| S16 | `--offline-search`, `--offline-search-path PATH`    | Persists seen results, reloads before searching; explicit path enables it. Default `./camply_campsites.json`; JSON or `.pkl`/`.pickle`. Does not eliminate network requests. Writes when newly found results increase the set.                                        | Preserve JSON history/cron suppression with validated import and atomic writes. Reject pickle with export guidance; do not deserialize executable state. Keep historical records distinct from live availability. |

Source nuances: Click advertises case-insensitive weekdays, but the old flag-path dictionary lookup uses the original token and can fail on lowercase input. End-date prose in the old guide sometimes disagrees with the exclusive implementation. These are defects/documentation errors, not desired compatibility.

## YAML contract

The old file has these exact keys, from `YamlSearchFile`:

| Keys                                                | Shape and default                                                           |
| --------------------------------------------------- | --------------------------------------------------------------------------- |
| `provider`                                          | Case-insensitive legacy name; `RecreationDotGov`.                           |
| `recreation_area`, `campgrounds`, `campsites`       | Scalar string/integer or list; null when absent.                            |
| `start_date`, `end_date`                            | Required date scalar or date list, paired in order.                         |
| `days`                                              | List of weekday names/abbreviations; null.                                  |
| `weekends`, `nights`                                | Boolean false; integer 1.                                                   |
| `continuous`, `polling_interval`                    | **True**, 10 minutes. Different continuous default from flag-only searches. |
| `notifications`                                     | Scalar or list of names; silent.                                            |
| `search_forever`, `search_once`, `notify_first_try` | Boolean false.                                                              |
| `equipment`                                         | One `[name, length]` pair or list of pairs; null.                           |
| `offline_search`, `offline_search_path`             | False; null (runner chooses default JSON path).                             |

The loader expands `${VAR_NAME}` in scalar values; missing variables are replaced with the variable's bare name. YAML supplies provider/search arguments wholesale: explicit search flags, including command-level provider, are bypassed. Because the schema supplies a provider default, that also overrides a root provider for omitted YAML provider. `equipment_id` is absent from the old schema/translation. Flag-path implicit-continuous logic is not reused by YAML, so combining `continuous: false` with notification/forever fields is inconsistent.

Replacement: retain listed keys, defaults, scalar/list normalization and file authority. Expand environment references consistently, but fail on missing variables. Reject unknown keys and inconsistent run modes with field paths; add `equipment_id` as an extension. For YAML, `search_once: true` overrides the implicit default `continuous: true`; explicitly contradictory true values fail. Apply implicit continuous triggers when YAML does not explicitly choose `continuous: false`; with explicit false, reject contradictory notification/loop requests. Document these repairs in migration notes.

The notification layer loads `~/.camply` without overriding process environment. The wizard covers common fields, not every optional setting above. `RIDB_API_KEY` overrides legacy RIDB discovery credentials; new public discovery may not need it. Preserve explicit credentials only where the replacement actually consumes them, and explain obsolete settings. Never carry embedded upstream service credentials forward.

MultiNotifier always includes silent logging, even when only external channels are requested. It supports terminal “last gasp” error messages after search attempts, except where a channel disables that behavior. Replace with one sanitized terminal failure event per selected capable channel; failure to send must not obscure the original error. Legacy sequential fan-out can abort on one channel's exception; replacement isolates channel outcomes.

## Intentional differences and exclusions

- Stable user outcomes and commands matter; byte-identical Rich layout, unordered set result order, tracebacks containing locals and arbitrary internal Python import compatibility do not.
- Replace pickle state with JSON; reject unknown YAML fields, missing environment references, invalid equipment lengths, ambiguous equipment context, impossible stays and invalid windows before requests.
- Retain lifetime seen-result suppression for CLI, independently of web alerts that can notify after an opening disappears and returns. Do not import a legacy history file into a live result cache.
- Retain checkout-exclusive dates; align expiration with current UTC rules and document timezone differences from legacy local-today behavior.
- Legacy installation (`camply` on PyPI, pipx, Docker, cron) is part of migration documentation. This repository currently publishes `camply-web`; do not take over the old PyPI name or `ghcr.io/juftin/camply` as part of parity implementation.
- No auto-booking, checkout, payment, hosted-account requirement, remote API CLI, shell-completion guarantee, or new JSON-output CLI contract is implied by the legacy surface.
