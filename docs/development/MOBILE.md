# Camply for Android and iOS

Camply's Tauri 2 mobile client opens the existing hosted React frontend. Python,
the database, provider scans, and notifications workers stay on your remote
server. Deploy the frontend changes in this feature to that server first.
The UI and `/api` must share an HTTPS origin. No CORS or authentication changes
are needed; sessions and CSRF continue to use their normal first-party cookies.
Auth0 still needs its existing HTTPS callback/logout URLs; verify that your
identity provider permits embedded WebViews before distributing an Auth0 build.

## Setup and run

Install the normal Node/pnpm dependencies (`task frontend:install`) and Rust.
Follow the [Tauri mobile prerequisites](https://v2.tauri.app/start/prerequisites/)
for Android Studio, SDK, NDK, JDK 21 and Rust Android targets. iOS requires macOS,
Xcode, Apple signing configuration and the Rust iOS targets. Put Cargo's bin
directory on PATH. There is no Python runtime in the app.

Android tasks select JDK 21 from a compatible `JAVA_HOME`, Android Studio's bundled JBR, or an installed macOS JDK discovered by `/usr/libexec/java_home -v 21`. An inherited Java 27 is skipped. If JDK 21 is unavailable, install it and set `JAVA_HOME` to its installation directory; the task fails early with that guidance.

The Taskfile explicitly exports `JAVA_HOME`, `ANDROID_HOME`, `NDK_HOME`, and a `PATH` with the selected JDK and Android platform-tools first. This overrides conflicting exported shell variables. Existing `ANDROID_HOME` and `NDK_HOME` values are preserved. Otherwise the SDK defaults to `~/Library/Android/sdk` on macOS or `~/Android/Sdk` on Linux, and the newest stable installed NDK under the SDK's `ndk/` directory is selected. Install missing SDK/NDK components through Android Studio's SDK Manager. iOS and non-Android tasks do not perform Android toolchain discovery.

From the repository root:

```bash
export CAMPLY_MOBILE_URL=https://camply.example.com
# Generate the platform project once on the appropriate host:
task mobile:android:init
task mobile:android:dev
# Or on macOS:
task mobile:ios:init
task mobile:ios:dev
```

Use an actual HTTPS server accessible from the device. `localhost` on a phone
refers to the phone. The configured URL is the origin of the hosted app, not an
`/api` URL. Credentials, URL paths, query strings and fragments are rejected.
The app fetches current deployed assets, so updating the remote frontend updates
the mobile UI too. Offline use is not supported.

## Native notifications

Sign in and tap **Enable mobile notifications**. The OS permission prompt is
shown only after this action. Permission denial and refresh failures appear in
the app. Disable with the same button; preferences are scoped to the account.
Only the configured deployment origin can invoke the native notification plugin.
External booking and authentication origins receive no native permissions.

While the app is active it checks active scans every minute. The first successful
snapshot establishes a baseline without alerting about old results. Later new
campsite/date pairs trigger a native notification, including replacements where
the total count stays constant. Unchanged results do not repeat. Reopening the
app establishes a fresh baseline. Open Camply and view the saved scan to inspect
results; notification taps do not deep-link to individual scans.

These are **local notifications**, not remote push. Android and iOS can suspend
the app in the background, and polling does not run after it is terminated. Keep
server-side Pushover alerts configured for background delivery. Reliable native
background alerts require a follow-up APNs/FCM token registration and delivery
integration with server credentials; the official Tauri notification plugin does
not provide that service.

## Build and verify

```bash
task mobile:test
task frontend:check
task mobile:android:build -- --apk
# On macOS with signing configured:
task mobile:ios:build
```

Generated projects are in `src/tauri/gen/android` and `src/tauri/gen/apple` and
are checkout-local. Native artifacts are generated by Tauri/Gradle/Xcode there;
these commands do not publish anything. Set your own application identifier in
`src/tauri/tauri.conf.json` before initializing a production app. App icons derived from the existing Camply favicon are included. Regenerate them with `TAURI_APP_PATH=src/tauri pnpm exec tauri icon src/frontend/public/favicon.svg` before platform
initialization, and configure Android signing or your Apple development team in
the generated projects before distributing. Reapply signing settings if you
regenerate those ignored projects.

The native application, icons, and config tooling live under `src/tauri/`. Mobile tasks set `TAURI_APP_PATH` to that directory and keep `TAURI_FRONTEND_PATH` at the repository root so commands still run from the root.

The config task writes `build/mobile/tauri.remote.json` and binds both the WebView
URL and its minimal notification capabilities to the same trusted origin. All
mobile dev/build tasks regenerate it from `CAMPLY_MOBILE_URL`. Do not grant remote
wildcard origins or filesystem/shell permissions.

Before distribution, test on physical Android and iOS devices: first login,
logout/account change, permission accept/deny/revoke, first-result suppression,
a newly opened campsite/date, unchanged repeated results, offline recovery,
safe areas, and resume after suspension. Also verify your deployment's CSP allows
the Tauri notification bridge and that a page on another origin cannot notify.
Native compilation and device notification delivery require platform tooling;
frontend unit tests alone do not validate those behaviors.
